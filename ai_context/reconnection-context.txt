# Architecture Context: Session Persistence & Reconnection

## Objective
Implement a robust "Reconnection System" that allows players to refresh the browser or briefly lose internet connection without being kicked out of the game room.

## Core Mechanism: "The Wristband Pattern"
We will use a persistent **Session Token** stored in the browser's `localStorage` to identify users, rather than relying on the ephemeral WebSocket connection ID.

## Implementation Requirements

### 1. Data Structure Updates (Server)
Update the `Player` interface to include identity persistence fields:
- `token`: string (UUID, private, sent to client only once).
- `isConnected`: boolean (Tracks active WS status).
- `disconnectTimeout`: Timer | null (For grace period handling).

### 2. Protocol Flow

#### A. Initial Join (New Player)
1. Client sends `JOIN_ROOM`.
2. Server generates a `playerToken` (UUID).
3. Server creates Player object and adds to room.
4. Server responds with `WELCOME`:
   - Payload: `{ token: "uuid-...", playerId: "...", ... }`
5. **Client Action:** Save `token` and `roomId` to `localStorage`.

#### B. Disconnection (Socket Close)
1. Server detects `ws.on('close')`.
2. **CRITICAL:** Do NOT remove player from the room array immediately.
3. Server marks `player.isConnected = false`.
4. Server starts a **Grace Period Timer** (e.g., 60-120 seconds).
   - If timer expires: Remove player permanently.
5. Server notifies room: `PLAYER_DC` (UI should show "Disconnected" icon).

#### C. Reconnection (Page Refresh)
1. Client App mounts.
2. Check `localStorage` for `rubsarb_session`.
3. If found, Client sends `RECONNECT`:
   - Payload: `{ token: "uuid-...", roomId: "..." }`
4. **Server Action:**
   - Find player by `token`.
   - If found:
     - Cancel Grace Period Timer.
     - Update `player.ws` to the new socket instance.
     - Mark `player.isConnected = true`.
     - Send `WELCOME_BACK` with full game state (Hand, Board, Topic).
     - Notify room: `PLAYER_RECONNECTED`.
   - If not found (Expired/Invalid):
     - Send `ERROR: SESSION_EXPIRED`.
     - Client must clear `localStorage` and redirect to Home.

### 3. Best Practices
- **Security:** The `token` acts as the password. Do not broadcast it to other players.
- **UI:** Disconnected players should remain visible on the board (greyed out) so the game state remains consistent for others.

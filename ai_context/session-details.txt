# Architecture Context: Session Management (Option A - Auto-Rejoin)

## Core Philosophy: "Logged In Until Logged Out"
We are choosing **Option A (Discord Style)** for session persistence.
- **Behavior:** If a user refreshes or closes the tab, they are **automatically** reconnected to their active room immediately upon loading the site.
- **Goal:** Minimize friction. Connectivity glitches should not force the user to re-type their name or room code.

## 1. Client-Side Logic

### A. Initialization (`onMount`)
1. Check `localStorage` for `rubsarb_session` (contains `token`, `roomId`).
2. **IF Found:**
   - Skip the "Main Menu" / "Landing Page" entirely.
   - Immediately open WebSocket.
   - Send `RECONNECT` (or `JOIN_ROOM` with token).
   - Show "Reconnecting..." spinner until `WELCOME_BACK` is received.
3. **IF Not Found:**
   - Show Main Menu (Name Input, Join/Create Buttons).

### B. The "Escape Hatch" (Explicit Logout)
Since the user is trapped in the room by auto-rejoin, we MUST implement a **"Leave Room"** button in the Game UI.
- **Action:** User clicks "Leave Room".
- **Logic:**
  1. Send `LEAVE_ROOM` to server.
  2. `localStorage.removeItem('rubsarb_session')`.
  3. `window.location.reload()` (Forces return to Main Menu).

---

## 2. Server-Side Logic (Identity & Name Changes)

### A. The "Identity Update" Rule
**Scenario:** A user manually modifies their local state or uses a custom client to send a `JOIN_ROOM` request with:
- An **Existing Valid Token** (matches a player in the room).
- A **Different Name** than what is currently stored.

**Server Logic:**
1. Lookup player by `token`.
2. **IF Found:**
   - **Trust the Token:** This is the same person.
   - **Update Name:** Overwrite `player.name` with the new name from the payload.
   - **Reconnect:** Cancel grace period, update socket.
   - **Broadcast:** Send `PLAYER_UPDATE` to the room so others see the name change.
   - **Do NOT** create a duplicate player entity.

### B. The "Ghost" Cleanup
1. **Disconnect:** When socket closes, mark `isConnected = false`, start `disconnectTimeout`.
2. **Rejoin:** When socket opens with known token, `clearTimeout`, set `isConnected = true`.

---

## 3. Summary of User Flows

- **User Refreshes:** Auto-rejoins same room, same name.
- **User Closes Tab -> Reopens:** Auto-rejoins same room, same name.
- **User Wants New Name/Room:**
  1. User must click "Leave Room" inside the game.
  2. User lands on Main Menu.
  3. User enters New Name / New Room.
  4. Client has no token -> Sends `JOIN` -> Server generates **NEW** Token -> New Identity.
